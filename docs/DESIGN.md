# 如页 · 设计说明（简版）

完整需求来自最初的设计说明书（v1）。本文记录实现时的关键设计，以及**与原说明书的差异和理由**。

## 核心原则

1. 预览即导出：唯一排版器是 Typst（typst.ts v0.7，内置 Typst 0.14）。`LayoutEngine.svg()` 和 `LayoutEngine.pdf()` 接收完全相同的 Typst 输入。
2. 诚实命名：A4 智能一页 ≠ 无损长一页。
3. 可读性底线：正文与次级文字 ≥ 10.5pt，姓名 ≥ 16pt，模块标题 ≥ 11.5pt，行距 ≥ 1.35，页边距 ≥ 12mm。由 `checkTokenFloors()` 和测试共同保证。
4. 装不下就说人话：溢出报告来自真实排版，不按字数估算。
5. 本地优先：localStorage，PDF 在浏览器里生成。可选的同步后端只做多设备同步，不参与排版；不登录时前端不发出任何请求。

## 数据流

```
RuyeDocument ──renderableModules()──▶ 模板 build() ──▶ { main.typ, data.json, tokens.json, page.json, photo.* }
                                                              │
                                              typst.ts（唯一排版器）
                                                 ├── svg  → 预览 + 测量（根元素 data-height）
                                                 └── pdf  → 导出
```

## 测量

- `contentHeightMm`：用 `page.height = "auto"` 编译一次。Typst 会让页面高度等于内容高度（含页边距），直接读 SVG 根元素的 `data-height`。
- `pageCount`：用固定 297mm 编译，typst.ts 的 SVG 把各页上下叠放，总高 ÷ 297 即页数（不是整数时报错，防止静默出错）。
- 模块 / 条目占高：把它从文档里拿掉重排一次，差值就是它的真实高度（含间距）。只在溢出时计算。

## fit-a4 算法

```
默认 token 装得下 → fitted-default
按步骤收紧，每个连续步骤试 25% / 50% / 75% / 100%（默认 → 底线），第一档装下就停 → fitted-tightened
全部推到底线仍装不下 → overflow + 2～4 条建议（不删任何内容）
```

「装得下」= auto 高度 ≤ 297mm **且** 用固定 297mm 复核确实只有 1 页。

## 与原说明书的差异

| # | 原说明书 | 现在的实现 | 理由 |
|---|---|---|---|
| 1 | 产品名「一页（Yiye）」 | 「如页（Ruye）」，取「所见如页」 | 「一页」太通用、搜不到，也和「一纸简历」相近 |
| 2 | 收紧顺序：间距 → 行距 → 字号 → 紧凑变体 | 间距 → **紧凑变体** → 行距 → 字号 | 原文第 4 节原则写的是「宁可变紧凑模块，也不破坏阅读」，与原顺序矛盾 |
| 3 | 伪代码每步一次 `tighten` | 每步分 4 档试探，第一档能装下就停 | 原文字说明要求「一旦装下即提前停止」，伪代码会直接降到底线 |
| 4 | 长一页先估高再二次测量 | Typst `height: auto`，一次排版即精确 | 估算 + 校正是为 react-pdf 设计的，Typst 不需要 |
| 5 | 数据可「写成临时 .typ 变量文件」 | **只**通过 JSON 文件注入 | 拼接 Typst 源码时，用户文本里的 `# * _ $ @ <` 会被当成 Typst 语法解析 |
| 6 | 只有 short / long 两份样本 | 增加 `medium`（默认约 1.05～1.2 页） | long 在底线下基本装不下，「收紧后成功」这条路径没有样本覆盖 |
| 7 | 字体子集「国标一级字」 | GB2312 全部 6763 字 + 常用符号，导出前做缺字检查 | 一级字只有 3755 个，姓名、学校名常超出 |
| 8 | Zod 校验 | 零依赖手写校验器（原文允许「或同等」） | 不装依赖也能跑 schema 测试 |
| 9 | Vitest | Node 内置 `node:test` | 零依赖，Node 22 可以直接运行 TypeScript |
| 13 | 求职意向是独立模块 | 渲染时并入页眉，数据上仍是独立模块 | 单独占一个模块标题太浪费一页的空间 |
| 14 | 照片「最简方形裁切」 | 3:4 居中裁切 | 中文简历照片习惯用证件照比例 |
| 15 | 智能一页只收紧 | 内容明显不满一页时在上限内放宽间距与行距（`fitted-relaxed`） | 大半页空白看起来像没写完；字号与页边距不动，仍然诚实标注 |
| 16 | 双栏左栏内容固定 | 按实测高度自动决定教育、获奖放哪一栏 | 内容多少不同时，固定分配容易一栏满一栏空 |
| 10 | standard 的 `overflowMm` 语义含糊 | standard 恒为 0 | 分页模式没有「溢出」 |
| 11 | `FitStatus` 五种 | 增加 `too-long` | 长一页超过 4 页 A4 上限时需要一个失败状态 |
| 12 | 次级文字底线未明确 | 次级文字（日期、电话）同样 ≥ 10.5pt | 原文 6.3 第 5 步「正文及次级文字 ≥ 10.5pt」 |
| 17 | 无后端、无账号 | 默认仍无后端；新增**可选**的 Spring Boot 同步后端（`server/`），构建时设置 `VITE_RUYE_API` 才显示登录入口 | 多台电脑之间切换编辑是真实需求；保持「不登录也完整可用」，本机始终是主副本 |

### 色板（v4）

每个主题一整套颜色，定义在 `common.typ` 的 `palettes`：`primary` 深主色（标题、强调文字）、`secondary` 鲜明辅色（图形、色块）、`bright` 亮色（渐变另一端、深色底上的强调）、`tint` 极浅底色（胶囊）。文字只用 `primary`，`secondary` / `bright` 只用于图形与大面积色块，保证打印对比度。schema 的 `THEMES` 记录主色与辅色（编辑器色块显示为渐变），有测试保证两处一致。

模块图标（教育、技能、工作 / 实习、项目、科研、论文、获奖）与联系方式图标都是原创的 24×24 线性 SVG，按主题色着色。

共同细节：
- 联系方式图标是原创的简单线性 SVG（手机、信封、定位、代码括号、链接、人像）。
- 求职意向并入页眉（岗位加粗，不加图标）；照片为 3:4 证件照比例，裁切填满。
- **经历头部**：标题行（单位粗体、岗位强调色、日期右对齐等宽），下面是带标签的「简介：……」「技术栈：……」两行（项目写作「项目简介」）。技术栈是强调色文字、细圆点分隔，不用底色标签；项目链接放在技术栈行末尾，不挤标题行。
- **要点的结构（v5）**：不改数据结构，只看字符串本身。单独一行、以冒号结尾的短句（「个人职责：」「技术亮点：」）渲染为主色加粗的分块小标题，不带圆点，并与下一条要点绑在一起不跨页；句首 1～14 字的短语加冒号（「防止超卖：……」）加粗冒号前的短标题。这是国内技术岗简历最常见的写法，招聘方扫读时能先看短标题再决定读不读整句。
- **自我评价（v5）**：新增 `summary` 模块，`data.text` 一段文字，换行分段，排在最后。Markdown 标题「自我评价 / 个人评价 / 个人总结 / 个人优势」都能识别。
- 量化成果自动加粗：带单位的数字（320ms、85%、3 天）和两位以上整数；型号、版本号（P99、A4、OAuth 2.0）不加粗。
- 标题行不做两端对齐，避免折行时把字拉散。
- 紧凑变体：技能在每行都放得进半栏时改成双列（用 `measure()` 量实际宽度判断）；模块标题与内容的距离更近。

### 内容不满一页时放宽（A4 智能一页）

原说明书只要求「装不下就收紧」。内容明显不满一页时（留白超过 6mm），引擎会在上限内放宽间距与行距，让页面自然填满，状态为 `fitted-relaxed`，界面写明「已适当放宽间距与行距」。

- 只动间距和行距：间距最多放大到默认的 1.6 倍，行距最多 +0.12（且不超过 1.75）。字号、页边距从不改变。
- 二分查找能装进一页的最大放宽量，每一档都用真实排版复核；离页底 3mm 以内就停。
- 上限放到底仍有留白时就保留留白：再拉开会显得松散。
- 标准分页、长一页不放宽。

### 双栏自动平衡

双栏紧凑模板在 Typst 里用 `measure()` 实测几种分配方式的两栏高度：技能 / 教育 / 获奖都在侧栏、教育挪到主栏、获奖挪到主栏、只留技能。选两栏中较高者最矮的一种；至少矮 3mm 才换方案，避免为了一点点高度把模块挪来挪去。技能里有描述句时整个技能模块固定放主栏。

## 编辑器

- 文档（`RuyeDocument`）是唯一事实来源；所有修改都走 `apps/web/src/doc-ops.ts` 里的纯函数，有单元测试。
- 删除条目、类别、模块后可以撤销（保留一步）。
- 照片在浏览器里按 3:4 居中裁切、缩到 360×480，转成 JPEG data URL；超过 1MB 的原图直接拒绝。
- 状态管理用 React 自带的 state，没有引入 Zustand：目前只有一份文档，用不上。

## 页数与页码

- 页数来自 typst.ts SVG 里每个 `<g class="typst-page">` 分组，也就是 Typst 实际分出的页；找不到分组时才退回「总高 ÷ 页高」。typst.ts 会把 SVG 里的页面尺寸取整到 1pt（约 0.35mm），所以「装得下」判断之后还会用固定 297mm 再编译一次，复核确实只有 1 页。
- 多于一页时，模板在页脚右下角印「当前页 / 总页数」（`common.typ` 的 `page-footer`），字号同次级文字。页码画在下页边里，不占版心，不影响测量。单页（A4 智能一页、长一页）不印页码。
- 导出走 `LayoutEngine.exportPdf()`：生成 PDF 后读取 PDF 自身的页数（页面树的 `/Count`），与排版结果不一致就报错，不交出页数和界面说法不符的文件。
- 标准分页时，条目的标题、简介、技术栈和第一条要点绑成一个不可拆分的块，不会出现「标题在页底、要点全在下一页」。

## 安全

导入的 `.ruye.json` / Markdown 可能来自别人。预览 SVG 会被插进编辑器页面，所以链接做三层限制：

1. 校验器：网站、GitHub、博客、自定义链接、项目链接、论文链接只接受 http、https、mailto，或不写协议（排版时补 `https://`）。
2. 模板：`safe-url()` 只为这些协议生成可点击链接，其他协议只显示文字。
3. 引擎：`LayoutEngine.svg()` 返回前用 `sanitizeSvgLinks()` 把不安全的 `href` 换成 `#`。

用户写的文字本身由 typst.ts 转义，不会被当成 HTML。照片只接受文件头校验通过的 PNG / JPEG / GIF / WebP，数据损坏时跳过照片，而不是让整份简历编译失败。

## 专业技能

- 数据：`categories`（分类 ｜ 技能、技能）和可选的 `notes`（描述句）。只填一种就是那种写法，都填就是混合写法，排版时先分类后描述句。
- 描述句用要点圆点排版：句首是「Java 基础：……」时加粗冒号前的关键词；否则把句首的熟练度词（精通、熟练掌握、熟悉、掌握、理解、了解、擅长、具备、能够）用强调色加粗。
- 双栏紧凑模板的侧栏只有 58mm，放不下整句描述，所以技能里有描述句时整个技能模块改放右侧主栏。
- Markdown：分类名加粗（`- **语言**：Java、Python`），描述句是普通要点；只要出现过加粗分类就按新格式严格区分。旧文件没有加粗时，「名称：内容」且内容里没有句读的行算分类，其余算描述句。

## 排版线程

- 排版跑在 Web Worker 里（`apps/web/src/layout.worker.ts`）：A4 智能一页最多要试排二十多次，放在主线程会让输入卡顿。
- `scheduler.ts`：同一时间只跑一个任务（typst.ts 的影子文件系统是全局状态）；导出任务全部执行并优先；预览只保留最新的一个，排队中的旧预览直接作废。
- `layout-service.ts` 是纯逻辑，Worker 和主线程退路共用，并且在 Node 里用真实 Typst 测试。浏览器不支持模块 Worker 或 Worker 初始化失败时，`layout-client.ts` 自动退回主线程。
- Worker 里的相对路径是相对 Worker 脚本解析的，所以字体和 wasm 的地址由主线程按页面地址算好后传入。

## 左栏

- 分「内容」「模板与样式」两个标签页，减少滚动。内容页顶部是当前样式摘要（缩略图、模板名、主题色、页面模式），点一下切到样式页。
- 模块列表每行一个原创线性图标；悬停时显示拖动把手与上下移动按钮，眼睛图标切换显隐（隐藏的模块名称加删除线，内容保留）。缺少的模块以「＋ 模块名」标签列出，一键添加。
- 模板缩略图由 `scripts/thumbs.py` 用真实排版生成（同一份完整示例，A4 智能一页，量化为 48 色 PNG，七张共约 160KB），看到的就是排出来的样子；按「稳妥 / 设计感」分组。

## 可选云同步

- 后端在 `server/`（见 [server/README.md](../server/README.md)）：JWT（HS256）无状态鉴权，BCrypt 存密码，同一邮箱连续失败 5 次锁定 15 分钟；简历按账号隔离，原样存储前端的文档 JSON，每次写入版本号加一，写入时带 `baseVersion`，不一致返回 409；删除是软删除。
- 前端 `apps/web/src/sync.ts`：`planSync` 是纯函数，按「本机内容指纹、云端版本、上次同步记录」三方比较决定动作：只有本机改过 → 上传；只有云端改过 → 拉取；两边都改过 → 云端版本另存为新简历（备注名标注「云端冲突副本」），本机版本基于云端最新版本上传；云端删除而本机没改 → 本机保留并停止同步；本机删除且云端仍是上次版本 → 同步删除。内容指纹忽略 `updatedAt`。
- 正在编辑、尚未写入本机的当前简历不会被云端版本覆盖（这一轮跳过）。首次打开时自动载入、还没改过的示例不上传。
- 触发时机：登录后立即、内容变化 5 秒后、切回窗口时、手动「立即同步」。登录失效时自动退出登录，本机内容不受影响。

## 多份简历

- 存档格式不变：`ruye:documents` 是 `{ id, doc }[]`，保存时当前简历排到最前（即「最近使用」顺序），`ruye:currentId` 记录上次打开的那份。
- 新建、载入示例、导入、复制都另存为新的一份，不再覆盖当前简历。只有本地存档读不出来、用户确认要重新开始时，才整体替换。
- 首次打开自动载入的示例如果还没改过，新建或导入时直接复用它的位置，列表里不会堆积示例。
- 备注名（`meta.alias`）只在列表里显示，不出现在 PDF 里；类型不对时恢复草稿会丢弃它，不连累正文。
- 读不出的条目在列表里跳过，但保存其他简历时原样保留，不会被删掉。

## 已知限制（v0.1）

- 缺字时只报告缺哪些字，还不会自动加载完整字体。
